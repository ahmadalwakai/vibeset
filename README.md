# Vibeset

Vibeset is a free English/Arabic platform for phone wallpapers, matching icon packs and decorative widget designs. The web implementation includes the searchable catalogue, theme downloads, Studio remixing, saved collections, creator tools and administrator workflows. It uses Next.js 16 with Cache Components, React 19.2, Chakra UI v3, Neon/Drizzle and guarded Better Auth endpoints.

Local implementation and verification are progressing through the ordered phase prompts. Live provider verification, launch requirements and the later native companion/TestFlight submission remain pending; the phase records below distinguish completed checks from those open gates.

## Local development

Use Node 24 (`.nvmrc`), then run:

```sh
npm ci
npm run chakra:typegen
npm run dev
```

Open http://localhost:3000 for English or http://localhost:3000/ar for Arabic. Home, Explore, theme details, Studio, setup guides and signed-in workspaces are implemented. Locale switching preserves the current path and query. Mobile has a five-tab bottom bar; desktop uses the header navigation. Private tools require the relevant account role, and data-backed pages require the configured development database.

For a fresh checkout, copy `.env.example` to `.env.local` and supply the public site/CDN URLs for the shell. Supply real Neon URLs, Better Auth URL/secret, IP hash salt, cron secret and internal API secret before using the database/auth modules. Server configuration is validated when its module is imported; missing values produce key-specific errors. Credentials are never checked into this repository.

## P05 storage and publishing

Publishing renders matching wallpapers, previews, thumbnail and OG assets into an isolated UUID attempt path inside each asset version. A short transaction verifies the captured status, spec hash and version before updating the theme and audit atomically. Concurrent or failed attempts cannot delete another attempt's files. Lost commit acknowledgements preserve uploaded files; retrying without `--force` repairs cache invalidation and retention without rerendering unchanged assets. Retention keeps the current and previous versions.

The state machine validates actor rights, source, ownership and submission requirements. Its conditional update/audit statement cannot record a successful transition when the state is stale, and it rechecks creator approval at submission. Publishing is the only path into `published`. Storage validates paths, streams bounded object reads, signs content-type-bound PUT URLs and handles pagination and partial deletion failures. Phone JPEGs and thumbnails must meet their 3,000,000-byte and 80,000-byte budgets before upload.

```sh
npm run themes:sample
npm run themes:publish -- --status=approved --concurrency=3
# Use --ids=<comma-separated UUIDs> to retry specific themes, or --force to render another version.
```

The sample helper is idempotent and refuses production. The publish CLI validates selection, reports per-item results, drains active work on interruption, and prints explicit retry commands for post-commit failures.
